## 1. 论文定位与开篇主张

这篇文章要讲清楚：**化学信息学工具与计算算法提供实际求解能力，科学校验约束结论，DAG 组织任务并承载证据，引导式报错帮助 Agent 从失败中恢复；Cloudra 将这些因素结合起来，面向自主反应机理研究。**

开篇可以将“这些因素共同增强 Agent 能力与可靠性”作为需要检验的中心主张。结果出来后，再按证据决定能写成多强的结论。不能仅凭架构存在就写“已证明提升”，也不能要求每个底层算法都具有单独的首创性。

写作的重心：

- **算法是重要内容。** 解释结构、路径、构象、过渡态与证据处理等实际计算能力如何支持机理研究，而不只列工具名称。
- **DAG 是设计载体，也直接参与工作。** 它连接研究目标、计算、证据和交付状态；既不把它当唯一 novelty，也不把它写成仅用于展示的流程图。
- **校验与反馈要落实到动作。** 哪个检查发现了什么问题，是否实际阻止完整结算，Agent 看见了什么、如何改变下一步，均须从真实轨迹取证。
- **系统贡献与单模块效应分开。** 四组实验可支持特定策略组合的比较，但不能独立估计每个算法或 DAG 的增益。
- 与已有自动反应探索、量化工作流和化学 Agent 的关系据可核验文献写，不宣称“首次”或无证据贬低其他系统。本计划不新增未经核验的引用。

## 2. 主张与证据对应表

| 拟写主张 | 必须准备的证据 | 允许得出的结论及边界 |
| --- | --- | --- |
| 化学工具与算法使 Agent 能把机理假设推进到可检验的计算结果 | 实际使用的算法、输入输出、计算产物、成功与失败实例；初猜到后续计算的真实关联 | 支持所展示的能力与适用条件；算法说明或单例成功不能证明总体成功率提升 |
| 科学校验和强制干预有助于减少无依据的完成声明 | 独立科学审计；接受/拒绝与真值对照；A/B 配对结果、拦截与恢复事件、成本和人工介入 | A/B 估计 Supervisor 与强制科学结算等组合的效果，不能只归因于 Supervisor |
| DAG 把任务、证据与后续行动连起来 | DAG 版本变化、证据绑定、契约检查、失败处置及对应工具/事件记录 | 支持设计如何发挥作用；没有单独 DAG 对照时，不声称测得 DAG 的独立因果增益 |
| 可调用的独立校验与自动判定反馈会影响研究行为 | B/C 的实际工具、反馈与 DAG 差集；主动校验、错误识别、partial 和最终独立审计 | 当前是组合差异，包含 DAG 可见性和残余反馈，不能写成纯校验工具效应 |
| 引导式错误反馈可能改善恢复与计算效率 | A/D 的完整反馈与简略反馈样本、判定不变证据、后续动作、独立恢复结果及成本 | 对“较完整/较简略诊断反馈”的比较，不是“有/无任何提示”的比较 |
| 系统在某些任务类型上更有效，也有明确局限 | 预先定义的任务分类、各类分母、逐题结果、失败轨迹与不确定性 | 讨论观察到的适用范围；类别少样本、事后划分或嵌入图不能承担普遍性结论 |

每条主张保留反例。出现更多拦截但没有更高独立科学正确性，或恢复次数增加却只产生重复计算，都不能直接写成能力增强。指标没有改善时，应缩小或否定对应主张，而不是更换成功定义。

## 3. 正文结构：先让读者看见系统如何做事，再解释表现

以下是叙事顺序，不预设期刊强制章节格式。方法细节可按投稿要求另设 Methods，但不能把理解主结果所需的关键方法全部藏入 SI。

| 部分 | 中心问题与建议内容 | 写作前必须拿到的材料 |
| --- | --- | --- |
| 摘要与引言 | 为什么机理研究需要能算、能查证、能恢复的 Agent？给出上述主张、适用范围和贡献边界 | 最终主结果与限制；摘要最后写，不提前填提升数字 |
| 一个具体任务的完整过程 | 从研究问题到机理假设，建 DAG、调用算法、生成证据、发现失败、修正或 partial；让后面的架构有具体参照 | 可公开的完整轨迹、结构与日志、DAG 快照、失败及恢复事件、最终独立审计 |
| 架构与化学方法 | 上述过程为什么能运转？Agent、工具算法、DAG、科学校验、Supervisor、调度与持久记录分别负责什么？ | 冻结源码、接口与状态流、算法说明、真实计算链；区分确定性规则与模型判断 |
| Benchmark 与任务归属 | 测了哪些化学任务，覆盖与参考有什么限制？Agent 在哪些方向表现不同？ | 冻结题库/Gold、任务标签、逐题结果、参考质量与开发暴露记录、全部运行分母 |
| 轨迹行为分析 | 成功、失败与恢复是怎样发生的？哪些工具和策略被主动使用？ | 与原始日志相连的事件表、错误分类、行为计数、人工介入记录；语义空间探索可选 |
| 四组消融 | 在相同任务和资源规则下，已定义的三组比较支持或反驳哪些主张？ | 四组真实配置与差集、配对结果、误接受/误拒绝、成本、残余反馈检查 |
| 真实研究案例（可选） | 是否能协助解决课题组尚未发表的具体机理问题？贡献和仍需人工判断之处是什么？ | 获准使用的任务、真实计算、独立化学复核、人工帮助明细与披露边界 |
| 讨论与结论 | 能力在哪些条件下成立，哪里不足，哪些解释仍待验证？ | 正负结果、方法适用域、参考/预算/样本限制；结论强度不得超过证据 |

### 3.1 贯穿案例的写法

案例按真实时间顺序组织，不把失败删掉后拼成一次顺利完成：

1. **问题与假设：** 任务要求、初始已知信息、候选机理，以及 Agent 尚不知道的内容。
2. **DAG 建立：** 展示化学节点/边与研究目标的对应关系，而不是一张工具调用清单；区分候选与已支持的主张。
3. **算法与计算：** 指明哪个工具生成了什么结构或路径，随后用了什么方法、计算了什么。初猜和扫描峰不能直接叫过渡态。
4. **证据进入 DAG：** 让结构、原生日志、频率/路径证据与具体主张对应；必要时说明原生日志回退找到了哪些证据。
5. **失败由谁发现、由谁拦住：** 分开写计算引擎失败、工具科学检查、DAG 契约、Supervisor 和离线评价。并非每次警告都会在线拦截，也不是 Supervisor 自己生成科学真值。
6. **反馈与恢复：** 并列展示关键反馈、Agent 的下一步动作和新增证据；无效重试照实记录，不将工具返回正常当作恢复成功。
7. **最终交付：** 完整且正确、有效 partial、科学上有依据的否定，或尚未解决。指出仍缺什么，不用漂亮终图遮住缺口。

代表性案例按化学与工作流覆盖选择并说明选择规则。单例用来解释系统，不代替总体统计；必要时再配一个失败或 partial 对照片段。完整可复现 HTML 轨迹可作为配套材料，正文只截取支撑论点的片段。

### 3.2 Benchmark、轨迹与语义空间

任务归属先按明确的化学和工作流特征定义，再看成绩。使用冻结清单核对现有难度标签、单步/多步、竞争路径、构象与立体问题、方法边界等；允许一题多个标签，报告重叠，不为得到好看的差异事后改分类。

优先分析可审计行为：主动验证、首次失败后的策略变化、重复同类错误、有效新计算、过早声明完成、预算耗尽、人工介入和诚实 partial。关联原始事件，避免仅依赖模型对自己行为的总结。

可选的语义空间分析用于探索任务文本、失败描述或轨迹表示的相似性。说明嵌入对象、模型/版本、预处理与降维选择，回查代表点及反例，检查结果对表示选择是否敏感。不同任务、重复运行和同一轨迹片段不能混成独立样本；加入成绩标签后形成的图也不能再当作独立预测证据。

这部分可称任务和行为的可解释分析；不能从嵌入邻近、聚类形状或可见思维文字推出模型内部推理机制，更不能由此证明某个组件导致能力提升。若分析没有带来可核实的新认识，缩到 SI 或不放，不强行保留一张语义空间图。

### 3.3 四组对比的写法

| 组别 | 分支 | 论文中必须披露的实际处理 |
| --- | --- | --- |
| A 完整版 | `benchmark/arm-guided` | 工具、DAG、Supervisor 和强制科学完整结算保留；partial 依既有流程处理 |
| B 去强制干预 | `benchmark/arm-record` | 去掉 Supervisor 拦截，不主动因科学校验强行阻止结算；保留可主动调用的科学校验工具 |
| C 校验入口禁用、判定反馈模糊化 | `benchmark/arm-standard` | 独立 verify/strict 禁用；计算、测量和内部真实判断保留，公开自动科学结论中性化；实际还隐藏 DAG，并有残余信息渠道 |
| D 简略报错完整版 | `benchmark/arm-guided-brief-errors` | 与 A 保持工具、判定、阈值和拦截一致，仅缩短模型可见诊断；原始计算输出和混合科学文本仍可能带有引导 |

- A/B：强制干预组合效应，不能写成纯 Supervisor 消融。
- B/C：独立校验入口、判定反馈与 DAG 可见性等共同变化，不能写成单一工具或纯 DAG 效应。
- A/D：引导式诊断反馈的作用；D 是较简略反馈，不是所有引导归零。
- 三项对比均不独立识别某个底层算法的贡献，也不代表与其他 Agent 系统的性能比较。

统一模型、任务、预算规则、计算条件和独立评估；报告真正使用的分支/commit，而非只相信 mode 标签。四组各自从任务起点运行，不做现场分叉续跑；暂不扩成逐算法全量消融。正式实验的运行和停止条件沿用配套实验计划，不由本文另行规定。

### 3.4 完整、正确、partial 和分数

结果必须分别回答三个问题：

1. **完整吗？** 是否覆盖该任务要求的交付项目与证据，而非 Agent 有没有说 complete。
2. **正确吗？** 对实际交付且可判定的主张逐项独立审核；候选、无证据和无法判断单列，不以“未发现错误”代替已证实正确。
3. **完整且正确吗？** 完整任务契约是否被满足，且所需结论通过独立科学审核。这才支持完整科学成功的统计。

partial 允许交付候选、有效子结果和未解决问题，不要求所有产物事先在线验真；离线审计识别其中有效部分。partial 不能自动标为 verified，也不能并入完整成功率。

同时报告假成功、误接受/误拒绝、有效 partial、人工介入和实际成本。在线门禁的接受/拒绝与 Agent 最终的科学主张或拒答分开统计；没有该在线门禁的组，不将“不适用”记为零错误。明确全部计划任务、已启动任务、可评估任务、声称完成任务等分母，并给逐题配对结果及适当的不确定性；重复种子不算新的独立题目。

连续分数用于描述部分进展及误差结构。加权 0.9 不是 90% 成功率。当前原生日志 fallback 可以恢复部分绑定缺失的证据，因此缺正式工件或 `undelivered` 标签不能直接等同于科学零分。审查仍需确认实际有什么、缺什么。

### 3.5 可选真实案例与局限

课题组未发表机理案例只在时间、计算资源和披露权限允许时补充。把 Agent 初始知道的内容、研究人员已有答案、运行中人工帮助和最终独立判断分开；不能把已知答案回灌后的复现写成自主发现。发表或公开原始资料前另行确认授权，不在本计划提交中放入未发表化学细节。

讨论中保留用户原话“**多软结合体系**”作为待界定的类别。当前只有非正式低分观察，需先列出对应任务和化学特征，再依据干净重测判断问题是否存在、表现为何。不要擅自解释其含义，不预写“重测不会变化”，也不把少量低分直接归因为某个算法。

其他局限按证据讨论：计算方法适用域、参考答案质量、题目开发暴露、预算与搜索失败、运行故障、系统干预的代价，以及四臂混杂和残余反馈。清楚区分“目前做不到”“本次没测”和“已经有证据支持的边界”。

## 4. 架构、算法数学与 SI 的分工

正文需要能解释能力来源的方法，而不是只有工程示意图。完整可复现定义放在 Methods/SI，正文给出关键思想、输入输出、科学含义与实例。

| 内容 | 正文必须讲清楚 | Methods / SI 应准备的细节 |
| --- | --- | --- |
| 架构和状态流 | Agent 决策、化学工具、DAG 证据、Supervisor、异步作业及离线评价的职责；失败/partial 的返回路径 | 角色、工具集合、消息/事件顺序、实际接口、版本与恢复规则；避免把 runtime DAG 与评分图 schema 混为一谈 |
| 结构与初猜构造 | 原子映射、端点对齐、构象/路径候选如何减少模型直接编造几何；其失败边界 | 实际使用的映射与匹配、坐标变换、约束、单位、原子编号和构象选择规则 |
| 路径与几何算法 | 所用方法优化什么、输出是什么，为什么只是候选而非科学确证 | 目标函数、梯度或近似、耦合/约束、优化器、停止准则、数值稳定处理、初始化及版本；未使用的实验模块不凑作论文贡献 |
| TS 与科学校验 | 鞍点优化、频率与 IRC 方向证据如何串联；正常结束与科学有效不同 | 既有判据、可配置默认值、原生输出解析、映射/几何及端点证据关联；短 IRC 不要求自身走到底，不因写作另改阈值 |
| Benchmark 和独立审核 | 题库构成、参考适用域、完整/正确与部分分数的区别 | 冻结公式、逐项评分/否定规则、Gold 来源与缺口、分母、失败分类、统计与人工审计流程 |
| 复现材料 | 读者如何从代表图回到真实证据 | 逐题配置/版本/种子、输入、原生日志、结构、能量与状态索引、全量结果和 HTML 轨迹；数据许可与访问边界 |

**IDPP 的具体写法：** 当前 [实现说明](../docs/IDPP_MODES.md)区分 `standard` 与 `light`。standard 调用 ASE 的 IDPP 实现；light 保留旧的独立图像启发式优化。Methods/SI 应如实列出目标与权重、图像耦合、优化器、停止/退化处理和 ASE 版本，不能把二者包装成同一算法的等价实现。此处的 standard 是插值模式，与 C 分支的 standard 名称无关。

文件生成成功、优化满足停止条件、结构适合后续计算，以及 TS 最终通过校验，是不同事实。IDPP 修复或标准实现对齐只能支持实现层面的表述；没有匹配的下游结果，不能宣称提高了 TS 成功率。原始算法文献与软件来源在正式 Methods 中逐条核验后引用，本计划不补写未经检索的参考文献。

现有 [论文草稿](../paper/draft.md)、[章节目录](../paper/sections/)和 [SI 草稿](../paper/supplementary_information.md)作为素材入口，不视为已完成的新叙事。旧草稿的题数、评分逻辑、接口要求与未解决事项均须对照冻结版本更新，不能直接复制成当前事实。

## 6. 实际写作顺序

1. **整理证据清单。** 将已有材料标记为设计事实、工程测试、正式运行结果、非正式观察或待补证据；只用运行记录判定实验完成情况。
2. **选贯穿任务并整理完整轨迹。** 先写“发生了什么”，用真实事件确定图 1/2，保留失败和人工介入。
3. **写架构与化学 Methods。** 从该任务向外解释通用方法，补齐数学和参数来源，明确外部方法、本项目实现及实际改进的区别。
4. **冻结结果表与分析口径。** 与实验计划一致，列好完整/正确/partial、成本、任务分类及四臂差异；数据未齐时留待填，不写结果句。
5. **依据正式结果写 benchmark、轨迹与消融。** 先写逐项观察，再讨论解释与竞争解释；语义分析和真实案例只在有充分材料时加入。
6. **写局限与讨论，再定稿引言、摘要和标题。** 用最终证据反向检查开篇每条 claim，避免引言承诺多于结果。
7. **核对正文、SI 与复现索引。** 同一运行/结构/能量/版本在各处一致，图表可追溯；随后按选定期刊的实际要求调整格式。

不按固定日期承诺完成，也不把可选真实案例或语义分析变成启动主文写作的前提。先写已确定的方法与证据框架，结果部分等待真实数据。

## 7. 完成标准

- [ ] 开篇每条主张都能指向具体结果、原始证据或明确标注的设计说明；没有把待验证假设写成既成事实。
- [ ] 贯穿案例完整保留失败、恢复、partial/终态与人工介入，正文中的关键结论可追溯到原件。
- [ ] 化学算法与数学方法有足够篇幅，外部算法来源、工程实现、科学验收三者分清。
- [ ] 四组实际配置与差异核实；A/B、B/C 的混杂和 C/D 的残余反馈披露充分。
- [ ] 完整、正确、完整且正确、有效 partial、不可评估与假成功分开；所有比率有清楚分母。
- [ ] 语义分析没有越界为内部推理因果证明；单例没有被当作总体优势。
- [ ] “多软结合体系”仍按明确任务与干净重测证据讨论，没有未经确认的定义或预写结论。
- [ ] 旧草稿的历史数字和过时实现已排查；引用、表格、SI、运行版本及数据权限逐项核验。
- [ ] 公开 HTML 轨迹和 Drive 原始计算材料的范围、许可与可访问性确认后才发布；不因本计划推送而自动公开研究数据。
- [ ] 未完成实验、参考缺口及验证限制如实列出。局部软件测试通过不等于科学实验成功；CI 未执行也不能写成验收通过。
