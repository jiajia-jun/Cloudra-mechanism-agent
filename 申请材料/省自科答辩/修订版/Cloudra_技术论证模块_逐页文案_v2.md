## 1｜可靠运行：研究过程能被追溯和恢复

**归属：创新二——把常规运行负担交给系统**

**上屏正文**

- 一个机理任务会跨越多轮对话和多次耗时计算；系统必须清晰掌握“已经做过什么、还欠什么”。
- Cloudra 将关键状态变化记录为事件：先保存，再更新任务状态，最后执行外部动作。
- 判断规则写成可重复检验的函数；重启后可根据记录完整恢复研究进度。
- 关键状态变化记录为事件，重启后根据记录可完整恢复研究进度。

**讲述说明**：介绍系统的可靠运行机制：关键状态先保存再生效，确保即使遭遇意外中断也能完整审计并恢复科研进度。

**实现依据**：`cloudra/runtime_v2/commands.py`、`events.py`、`apply.py`、`persistence.py`。

## 2｜AgentHub：让专长不同的 Agent 直接协作

**归属：创新一的知识支持；创新二的协作基础**

**上屏正文**

- AgentHub 相当于研究组的讨论区：成员可以公开发现、提出问题，也可以直接请另一位专长 Agent 帮忙。
- 帖子与消息留下可追溯记录；新加入的 Agent 具备独立任务和生命周期。
- 同一入口还能检索带来源的化学知识，分层整合论文信息、已核实计算与模型假设。
- 这种设计显著减少固定“总指挥”逐项转述的负担，实现多智能体协同攻关。

**讲述说明**：展示 AgentHub 多智能体协作与知识检索：支持同级专长 Agent 之间的自组织协作，并分层整合文献知识、计算数据与预测假设。

**实现依据**：`cloudra/runtime_v2/hub_bridge.py`、`knowledge.py`；`cloudra/knowledge/plugin.py`。

## 3｜化学工具：覆盖从分子表示到结果解释

**归属：创新一——为 Agent 提供可选择、可检查的候选**

**上屏正文**

| 研究问题 | Cloudra 提供的能力 | 代表工具 |
| --- | --- | --- |
| 研究的是哪个分子、哪些原子在变化？ | 名称与结构转换、原子对应、反应中心识别 | `name_to_structure`、`reaction_mapping` |
| 分子可能怎样摆放和反应？ | 构象搜索、反应假设、过渡态初猜 | `conformer_search`、`mechanism_predict`、`ts_guess` |

**讲述说明**：展示专业化学工具覆盖：涵盖分子表示、三维构象搜索、过渡态初猜、量化计算调度与结果解释，为智能体提供扎实的操作能力。

**实现依据**：`cloudra/tools/registry.py` 及 `cloudra/tools/Chemtool/`。

## 4｜工作流：程序推进常规步骤，Agent 处理科学断点

**归属：创新二——把执行负担从 Agent 移出**

**上屏正文**

1. Agent 明确研究目标、反应物与候选路径，并作方法选择。
2. 工作流建结构、准备输入、提交计算、等待结果并解析输出。
3. 程序检查结果是否满足预先声明的条件；需要计算时继续推进。
4. 遇到原子对应错误、结构不合理或候选失败等断点，才把具体问题交还 Agent 判断。

**页末句**：Agent 负责“下一步研究什么”；系统负责“已决定的步骤可靠地做完”。

**讲述说明**：以过渡态搜索流程为例，启动后全自动推进建模、初猜和计算；在真正需要判断的断点处请智能体介入研判，实现高效率的人机分工。

**实现依据**：`cloudra/tools/Chemtool/ts_search_process.py`、`cloudra/scheduler/`。

## 5｜机理证据图：把“算过”与“证实”分开

**归属：创新三——可核查的机理交付，核心科学贡献**

**上屏正文**

- 图中的节点是反应物、中间体和产物；连线是提出的反应步骤。
- 每个需要证实的结构或步骤，都附有应完成的计算及其结果。
- 系统从已完成的计算文件提取证据，检查结构、振动、路径等条件；缺口继续保留。
- 最终是否完成，取决于实际计算证据覆盖情况，而非 Agent 的文字声明。

**页末句**：一份“机理答案”，必须同时给出路径和支持每一步的材料。

**讲述说明**：说明机理证据图的阶段契约：每个基元反应步骤均绑定量化收敛、虚频单一性与 IRC 路径连通等物理证据，杜绝模型幻觉。

**实现依据**：`cloudra/dag/models.py`、`completion.py`、`evidence_ingest.py`。

## 6｜记忆：保留可复用经验，但不把经验当证据

**归属：创新二的辅助能力**

**上屏正文**

- Agent 可以把通用的操作经验和失败教训写入长期记忆，供以后任务参考。
- 记忆会跨任务加载，内容过长时压缩并归档原文。
- 项目专属路径、编号等不应混入全局记忆；写入前有范围检查。
- 记忆优化“下次优先尝试什么”，保证经验积累与本次物理核验分层管理。

**讲述说明**：介绍经验记忆机制：在严格隔离项目私有数据的前提下，实现通用操作经验与调试策略的跨任务复用。

**实现依据**：`cloudra/persistence/memory.py`、`cloudra/tools/core/memory_scope_guard.py`。

## 7｜Benchmark：用不同困难检验科学判断

**归属：创新四——独立评价方法**

**上屏正文**

| 题目层级 | 主要考什么 | 代表体系 |
| --- | --- | --- |
| 基础题 | 能否给出自洽的结构和反应步骤？ | D1（一步反应） |
| 复杂题 | 能否组织多步机理与竞争路径？ | NQ1（多步与重排） |
| 立体选择题 | 能否区分空间摆法不同的竞争反应？ | HH1（轴构型竞争） |
| 方法边界题 | 当现有方法不能可靠计算时，能否标出不可达部分？ | IA1（电子结构边界） |

**页末句**：这套考卷全面考查计算、路径选择和方法边界三项能力。

**讲述说明**：介绍评测基准设计：覆盖基础单步、多步重排、三维选择性及方法适用边界，客观评估科学智能体在真实反应中的解决能力。

**实现依据**：`cloudra/benchmark/schema.py`、`gen_*_tasks.py`、`ideapool/tasks/`。

## 8｜Benchmark 评分：只看交付物，不看解释得多漂亮

**归属：创新四——独立评价方法**

**上屏正文**

- **机理覆盖（10%）**：提出的物种和反应步骤，是否对应参考机理？
- **证据自洽（30%）**：稳定结构、过渡态和路径，是否有相应计算文件支持？
- **结果准确（60%）**：关键能垒、性质或选择性，是否与参考答案相符？
- 评分读取交付图与计算日志，不读取 Agent 的结论性文字；每次运行保留独立记录。

**讲述说明**：介绍独立评分体系：完全以交付图和量化日志为输入，通过机理覆盖、证据自洽与结果准确三层严密打分，确保评价客观公正。

**实现依据**：`cloudra/benchmark/runner.py`、`graph_similarity.py`、`selfconsistency.py`、`accuracy.py`。
