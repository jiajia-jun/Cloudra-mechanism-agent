# 消融实验设计（v0，2026-10-22）

> 原则：**先确定要证明什么，再决定跑什么。** 不能反证任何命题的实验不做；能离线重算的，不重跑 agent。

## 0. 一句话背景

Easy 20 题已经全部跑通（20/20 落库）。在**当前 master 的评分口径**下离线重算：

| 指标 | 数值 |
|---|---|
| 平均 final | 0.908 |
| 平均 accuracy | 0.887 |
| 平均自洽（分级） | 0.9375 |
| `selfconsistency_passed` | 16/20 |
| final ≥ 0.99 | 11/20 |
| final ≥ 0.90 | 15/20 |

这组数字只说明"能跑"，还不能说明"这个基准测到了我们想测的东西"。下面的命题才是要证的对象。

## 1. 基准要支撑的命题

### P1（能力）Agent 能独立完成"机理 + 能垒"，且数值达到专家级

**需要的证据**
- 逐题：`accuracy` 与"日志推算能垒 vs Gold 能垒"的差值分布；
- 例证：easy 中 11 题 final ≥ 0.99；D4 的 exo 通道 11.28 vs Gold 11.30；G2 0.844 vs 0.870；F4 16.02 vs 16.02。

**反证（什么会推翻它）**
- 多数题 `accuracy` 高但 `graph`/`passed` 低 → 说明只是"碰数"，不是确定机理；
- 能垒误差呈双峰（要么 0 要么很大）→ 说明是抄参考而非计算。

**当前状态**：easy 上 `graph` 平均 0.90、`passed` 16/20，暂未出现反证；normal/hard/impossible 未跑。

### P2（证据纪律）高分必须由 agent 自己的原生 QM 日志支撑

**需要的证据（负控）**
- N1：交付一张数值正确、但沙箱里没有任何对应日志的图 → accuracy 必须为 0（双来源核对）；
- N2：把**别的题**的日志放进沙箱、图里写本题 Gold 数值 → 不得拿分（物种/几何不匹配）；
- N3：空交付/不可解析图 → 必须触发无证据倒扣（final = -1.0）；
- N4：声明与日志冲突、且证据里也没有能对上参考的组合 → fail-loud（final 只保留图分）。

**反证**：任一负控拿到 > 0.3 分 → 评分器有漏洞，**先修评分器，再谈重跑**。

**当前状态**：N3 有测试覆盖；N1/N2/N4 只有单元级覆盖，缺端到端负控沙箱。

### P3（评分效度）去掉档案格式要求不会奖励错误化学

这条是这次改动的核心辩护：分级 + 发现式检索 + 去 clawback，是"把格式噪声剥掉"，不是"放水"。

**需要的证据**：同一批沙箱、四种评分口径重算（零算力）：

| 臂 | 口径 |
|---|---|
| A0 | 旧：布尔自洽 + clawback + 能垒必须声明在边上 |
| A1 | 分级自洽，关闭沙箱发现（只认绑定） |
| A2 | 分级 + 发现，关闭节点能量兜底 |
| A3 | 当前 master |

**预期（可反证）**
- D4 / G2（数值对、只是没绑好/没声明）在 A0→A3 单调上升，A3 约 0.89 / 0.93；
- G3 / L2（TS 选错）在四个臂上都低（≤0.75），不因松绑而上升；
- 其余 15 题在四个臂上基本不动。

**反证**：G3/L2 或"错答案"的题在 A3 显著上升 → 分级口径确实奖励了错误，必须回退。

### P4（区分度）分数随难度分档下降，失败模式可归因

**需要的证据**
- 四档各一臂的平均 `passed` / `final`；
- 失败归因表：`short_irc` 证据缺失、TS 选错、参考态定义差异、格式/交付失败各占多少。

**反证**：hard 与 normal 无差异，或 impossible 的分主要来自格式而非"正确否定"。

## 2. 实验清单（按成本排序）

| 编号 | 实验 | 算力 | 依赖 |
|---|---|---|---|
| E1 | 四评分臂重算 20 个 easy 沙箱（P3） | 0 | 现成 run6 数据 |
| E2 | 端到端负控 N1/N2/N4（P2） | 0（合成沙箱） | 现有日志 |
| E3 | 绑定策略：required vs optional（prompt 变体），easy 20 题（P1/P3 的成本侧） | 重跑 2 臂 | 需先加 `--binding-mode` |
| E4 | normal / hard / impossible 各 1 臂（P4） | 重跑 3 臂 | 需先确认交付链路 |
| E5（可选） | 同题重复 2 次估计方差（P1 的置信区间） | 重跑 1 臂 | — |

**执行顺序**：E1 → E2 →（若 E1/E2 通过）→ E3/E4。E1/E2 不通过时不允许重跑。

## 3. 指标

主指标（分开报，不混）：

- `passed`：`selfconsistency_passed`，科学验收通过率；
- `final`：分级综合分（0.1 图 + 0.3 自洽 + 0.6 accuracy）。

次指标：`accuracy`、`graph`、`selfconsistency_score`、`undelivered` 比例、tokens、wall time、失败类型分布。

统计：以题为单位做**配对**比较（同题跨臂），报告中位数与配对 bootstrap 95% CI；n=20 时对 ~0.1 的均值差不敏感，结论只对 ≥0.15 的差异下判断。

## 4. 效度威胁

1. **LLM 方差**：同一题重跑分数可能波动；没有 E5 就不能把 <0.15 的差异归因于臂。
2. **环境漂移**：g16/PATH/网络（这次已见过 GitHub 与 LLM 的间歇故障）。
3. **评分器版本**：每臂必须记录 commit；A0 用旧 commit 或开关，不能改完再比。
4. **Gold 本身的不确定性**：D1 的 −3.1 kcal 可能是参考态口径问题而不是 agent 错，需要在报告里单列。
5. **泄漏**：题面含映射 SMILES 与参考产物；prompt 变体不能改变信息量。

## 5. 不做的事

- 不为提高分数放宽判据；
- 不把 `final` 当 `passed` 汇报；
- 同一臂内混用不同 commit；
- 用单次运行下结论；
- 在负控未通过时重跑 agent。
