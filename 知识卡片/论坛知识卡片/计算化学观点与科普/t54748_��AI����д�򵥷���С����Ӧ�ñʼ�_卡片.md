## 1. AI辅助计算化学编程的适用场景

利用Python编写脚本进行分子动力学（MD）数据分析或批处理时，若仅需使用bash和Python能实现的功能，可以使用AI工具辅助生成代码。AI辅助编程不仅限于编写Python脚本或伪代码，还包括调试代码和查阅文档，能够节省手动编写和Debug的时间。在时间紧迫的情况下，优先将AI作为提高效率的工具使用，而非深入学习所有底层编程知识。

---

## 2. AI编程工具的界面类型与趋势

AI编程工具主要分为Chat interface（对话界面）和Coding agent（编码代理）两类。目前业界趋势更倾向于使用Coding agent，推荐使用的模型包括Grok 3（特别是Think模式）等具备推理能力的模型。对于专注于科学计算的领域，建议关注能够抓取最新文献和方法的模型，而不仅仅是擅长写通用代码的模型。

---

## 3. Coding Agent 的工作原理与优势

Coding Agent 是一种具备增强功能的大语言模型（LLM），在复杂任务中表现优于简单的Chat interface。它能够根据用户需求自动拆解任务、规划步骤并执行，适合处理需要综合多个步骤或查阅大量文档的复杂计算化学编程任务。

---

## 4. Chat Interface 模式的 Prompt 结构

在使用Chat interface（如ChatGPT、Copilot）生成代码时，Prompt应包含四个核心部分：项目总体目标、代码能力要求、依赖库及环境信息（如conda environment yml）、以及参考文献或示例链接。这种结构有助于AI准确理解需求并生成兼容当前环境的代码。

---

## 5. Coding Agent 模式的 Prompt 结构

Coding Agent 的 Prompt 结构应包含：项目总体目标、具体的实现步骤、测试文件及数据说明。为了确保代理能够独立工作，必须提供详细的上下文信息，包括输入输出文件的格式、预期的分析步骤以及测试用例。

---

## 6. Chat Interface 模式的通用脚本撰写指令

在Prompt中需明确脚本的目标、通用要求及单位偏好。例如，指定使用MDAnalysis加载轨迹、NumPy进行数值计算，并要求优化代码效率（如减少for循环）。需指定输出文件的数据格式（如使用空格作为分隔符）和物理量单位（如能量用kJ/mol，距离用nm）。

---

## 7. Chat Interface 模式的库版本与环境兼容性指令

为了防止生成的代码与本地环境冲突，必须在Prompt中要求AI参考附加的conda环境文件。指令应明确要求确保脚本与环境中的库版本兼容，并在不确定时先询问用户再进行。

---

## 8. 脚本功能模块：内存估算与参数输入

脚本应包含估算运行时内存占用的功能。参数输入需通过命令行选项获取文件名（如topology.pdb, trajectory.xtc）、分析参数（如residue ID, 温度）及可选参数。所有默认变量必须在脚本开头定义，且建议使用argparse库合并常用参数。

---

## 9. 脚本功能模块：文件读取与缺失值处理

脚本需明确指定读取哪些文件以及文件中特定列的使用方式（如xvg文件）。对于缺失文件的情况，应设置预设值或发出警告。建议在分析前对轨迹进行对齐（例如基于蛋白质C-alpha原子）。

---

## 10. 脚本功能模块：计算与绘图的具体要求

Prompt需详细列出需要执行的分析方法（如根据参考文献计算CV值）和输出的文件类型（数据文件或绘图）。对于绘图参数，需指定图例大小、颜色、标签和误差棒等具体细节。可选功能应单独列出。

---

## 11. 脚本功能模块：日志记录与错误捕获

脚本必须将所有步骤记录到analysis.log文件中，并在任务结束后报告内存使用情况。需编写错误捕获代码，将所有错误信息记录到日志文件中，以便后续排查。

---

## 12. Coding Agent 模式的多阶段工作流

对于复杂的轨迹分析和gmx_MMPBSA结果处理，应要求Agent将工作流拆分为研究、规划、执行和检查四个阶段。Agent需生成子代理来分别执行这些阶段，包括查阅资料、编写计划、执行脚本和测试Debug。

---

## 13. Coding Agent 模式的输入输出与测试文件说明

Prompt需详细说明当前目录下的文件结构，包括系统拓扑文件、轨迹文件、ITP/NDX文件、处理脚本以及gmx_MMPBSA的计算结果。明确告知Agent哪些文件是输入数据，哪些是参考脚本，以便其正确调用和理解数据流。

---

## 14. Coding Agent 的安全与代码规范约束

在使用Coding Agent时，必须明确禁止其使用`rm`等危险命令，禁止直接修改原始输入文件。代码应具备通用性，避免硬编码路径，路径变量周围不应加双引号，并应使用向量化操作替代for循环以提高效率。即使在顶级LLM下，也需警惕内存泄漏或文件误删的风险，不宜直接用于生产环境的轨迹处理。
