## 1. WSL2 与虚拟机的选择

WSL2 相比于 VMware 等传统虚拟机，去除了完整的 Linux 图形界面和内核模块，不依赖图形化远程桌面。对于 CP2K、ABACUS、PySCF 等主要依赖命令行的计算化学任务，WSL2 的计算效率与 VMware 接近，且具有启动快、占用小、Windows 与 Linux 文件互通便捷的优势。

---

## 2. WSL2 常见问题

WSL2 在计算化学应用中存在三个常见问题：默认内存上限较低导致大任务无法运行；文件存放位置不当时（如 /mnt/c）会严重影响 I/O 性能；WSL 使用 .vhdx 虚拟硬盘，删除文件后虚拟磁盘占用的空间通常不会自动释放，需要手动优化。

---

## 3. WSL 发行版迁移至 D 盘

若需将默认安装在 C 盘的 WSL 发行版迁移至 D 盘或其他 SSD 路径，需按顺序执行以下命令：先查看发行版名称 `wsl -l -v`，随后关闭 WSL `wsl --shutdown`，导出系统 `wsl --export Ubuntu D:\wsl-backup\ubuntu.tar`，注销原实例 `wsl --unregister Ubuntu`，最后重新导入到新路径 `wsl --import Ubuntu-22.04 D:\WSL\Ubuntu D:\wsl-backup\ubuntu.tar --version 2`。

---

## 4. WSL 默认登录用户设置

完成发行版迁移后，首次登录默认为 root 用户，需恢复默认用户设置。可先列出 Linux 下的用户 `ls /home`，然后在 PowerShell 中执行 `wsl --manage Ubuntu --set-default-user 用户名` 即可将默认登录用户改回指定的普通用户。

---

## 5. .wslconfig 配置文件位置与作用

WSL2 的全局配置文件需在 Windows 用户目录下手动创建，路径为 `C:\Users\用户名\.wslconfig`。修改资料件后必须执行 `wsl --shutdown` 关闭 WSL，重启后配置方可生效，主要用于限制内存、处理崩溃转储及优化磁盘空间占用。

---

## 6. WSL2 内存限制配置

在 `.wslconfig` 的 `[wsl2]` 节下设置 `memory=120GB`，可强制为 WSL2 分配指定的内存上限。WSL2 默认仅使用 Windows 内存的 50%，对于大内存工作站可能导致计算崩溃，直接指定数值（如 120GB）可确保 WSL 能够利用足够的内存资源，同时保留一定空间给 Windows。

---

## 7. WSL 崩溃转储禁用配置

在 `.wslconfig` 中设置 `maxCrashDumpCount=-1` 可以禁用 WSL 的崩溃转储功能。此前运行 Gaussian16 时若强制中断（Ctrl+C），WSL 可能在 C 盘生成巨大的转储文件导致磁盘空间被占满，禁用该功能可避免在强制中断或 D 盘已满的情况下于 C 盘产生此类文件。

---

## 8. 稀疏虚拟磁盘 (sparseVhd) 配置

在 `.wslconfig` 的 `[experimental]` 节下设置 `sparseVhd=true`，可使新导入的 WSL 发行版使用稀疏 VHD 格式。启用后，当 WSL 内部删除文件时，Windows 能够自动回收虚拟磁盘的空间，无需手动压缩磁盘，从而避免 `ext4.vhdx` 文件只增不减的情况。

---

## 9. 旧版发行版启用稀疏模式

对于已存在的发行版，即使配置了 `sparseVhd=true` 也不会自动生效，需手动执行命令开启。操作步骤为：关闭 WSL `wsl --shutdown`，然后运行 `wsl --manage Ubuntu-22.04 --set-sparse true`，最后通过 `fsutil sparse queryflag "D:\WSL\Ubuntu\ext4.vhdx"` 查询，若返回 "This file is set as sparse" 则表示生效。

---

## 10. WSL 磁盘空间回收方法

若 Linux 内已删除文件但 Windows 磁盘空间未释放，在确保稀疏 VHD 已启用的前提下，可先在 WSL 内执行 `sudo fstrim -av` 清理未使用的块，随后在 PowerShell 执行 `wsl --shutdown` 关闭 WSL。重启后查看 Windows 文件属性，`ext4.vhdx` 的占用空间通常会有所下降。

---

## 11. 计算化学文件的存储路径规范

计算化学任务中的所有重型 I/O 操作，包括 conda 源码、临时计算目录及输入输出文件，应放置在 WSL 自身的 Linux 文件系统（如 `/home/用户名/project`）中。严禁将计算工作目录设在 `/mnt/c` 或 `/mnt/d` 等 Windows 挂载点上，因为跨文件系统的 I/O 性能较差且可能引发权限或兼容性问题。

---

## 12. ORCA 等软件的临时文件路径

部分软件（如 ORCA）会生成大量临时文件，若将临时目录指向 `/mnt/d` 等 Windows 路径，相比指向 `/home/用户名/project` 等本地路径会出现显著的性能下降，甚至导致运行异常。应确保此类软件的临时文件路径配置在 Linux 文件系统内部以保障运行效率。

---

## 13. WSL 与 Windows 的文件交互

若需将 Linux 下的计算结果复制到 Windows 中，使用 `cp result.xyz /mnt/d/results/` 命令即可。在 WSL 终端中执行 `explorer.exe .` 可直接在 Windows 资源管理器中打开当前 Linux 目录，方便通过图形界面管理文件。

---

## 14. WSL 文件路径的 Windows 访问

WSL 的文件系统可以直接通过 Windows 资源管理器访问，路径格式为 `\\wsl.localhost\Ubuntu`。通过此路径可以直接在 Windows 中查看、复制或编辑 WSL 内部的文件，无需使用命令行进行跨系统拷贝。
