## 1. 自行编译安装 CP2K 的必要性

自行编译安装 CP2K 源码可以实现对特定 CPU 指令集的优化，从而获得比官方 Docker 镜像更好的计算性能。对于使用 Slurm 等作业调度系统的高性能计算集群，通常需要将 Docker 镜像转换为 Singularity 格式才能使用，自行安装能更灵活地处理转换细节。从源码安装可以更详细地了解编译过程和依赖关系，方便后续的维护和定制。官方 Docker 镜像上传存在延迟，自行安装能够使用最新的源码版本。

---

## 2. 2023.1 版本 Dockerfile 修改与 CPU 指令集优化

CP2K 2023.1 版本目录下的 `build_dockerhub_images.sh` 脚本默认使用 `Dockerfile.prod_generic_psmp`，该文件调用 `install_cp2k_toolchain.sh` 时使用了 `--target-cpu=generic` 参数。这种通用配置会导致运行时针对当前 CPU 指令集进行即时编译（JIT），从而影响性能。若要追求极致性能，应将脚本中的 `Dockerfile.prod_generic_psmp` 修改为 `Dockerfile.prod_psmp`，以利用构建宿主机的 CPU 特性进行优化。修改时需注意构建环境 CPU 的指令集（如 AVX2 或 AVX512）必须与运行环境一致，否则可能导致运行错误。

---

## 3. 构建 CP2K Docker 镜像

进入 CP2K 源码包中的 `tools/docker` 目录，修改脚本以选择所需的 Dockerfile（如 `Dockerfile.prod_psmp`）。运行修改后的 `build_dockerhub_images.sh` 脚本，脚本将在当前系统上安装一个 Ubuntu 虚拟系统，并在其中下载依赖、编译 CP2K 源码及测试。该过程需要访问 GitHub 下载文件，建议配置相应的网络代理。编译完成后，系统会生成一个 CP2K 的 Docker 镜像。

---

## 4. 导出 Docker 镜像

Docker 镜像构建完成后，可以使用 `docker save` 命令将其导出为 tar 归档文件以便迁移。命令格式为 `docker save [IMAGE_ID] -o [FILENAME].tar`，例如将镜像 ID 为 `8cb745f97725` 的镜像保存为 `cp2k-2023.1.tar`。该文件包含了镜像的所有文件系统层，可用于后续的 Singularity 转换。

---

## 5. 转换 Docker 镜像为 Singularity Sandbox

使用 `singularity build` 命令将导出的 Docker tar 文件转换为 Singularity 的 sandbox 目录格式。命令示例为 `singularity build --sandbox cp2k-2023.1 docker-archive://cp2k-2023.1.tar`。Sandbox 模式以可读写的目录形式存在，方便用户在转换后的容器内部进行修改和配置。

---

## 6. 配置 Singularity 容器环境变量

使用 `singularity shell -w cp2k-2023.1` 进入可写模式的容器环境。需要在容器内编辑 `/.singularity.d/env/91-environment.sh` 文件，添加 CP2K 运行所需的环境变量配置。必须添加的配置包括：加载工具链环境 `source /opt/cp2k-toolchain/install/setup`，设置可执行文件路径 `export PATH=$PATH:/opt/cp2k/exe/local`，以及设置数据目录 `export CP2K_DATA_DIR=/opt/cp2k/data`。

---

## 7. 生成 Singularity SIF 文件

完成容器内部的软件和环境配置后，退出容器 shell。使用 `singularity build` 命令将配置好的 sandbox 目录打包为只读的 SIF（Singularity Image Format）文件。命令格式为 `singularity build [OUTPUT_FILENAME].sif [SANDBOX_DIRECTORY]`，例如 `singularity build cp2k-2023.1.sif cp2k-2023.1`。SIF 文件是运行 CP2K 作业的最终镜像格式。

---

## 8. CP2K 并行运行环境的一致性要求

在使用 Slurm 等调度系统的多节点并行环境下运行 CP2K，必须确保容器外的 MPI 环境与容器内的编译环境完全一致。关键的一致性要求包括：MPI 的类型一致、MPI 的版本一致、MPI 的编译器版本一致。容器内的 GCC 版本可通过 `gcc -v` 查看（如 2023.1 版本为 gcc-11.3.0），容器外的 MPI 必须使用相同版本的 GCC 进行编译。

---

## 9. GCC 11.3.0 编译参考

编译 GCC 11.3.0 时，首先解压源码包并运行 `./contrib/download_prerequisites` 下载依赖。建立 build 目录并执行 configure 配置，指定安装路径（如 `/public/opt/gcc-11.3.0/`）并启用 C、C++、Fortran 语言支持及关闭多库支持。配置参数示例为 `--enable-checking=release --enable-languages=c,c++,fortran --disable-multilib`，随后执行 `make -j 24` 和 `make install`。

---

## 10. MPICH 4.0.3 编译参考

编译 MPICH 4.0.3 时，需指定 GCC 11.3.0 作为编译器，并设置相应的编译优化参数（如 `-O2 -fopenmp -mtune=generic`）。执行 configure 时需明确设置 CC、CXX、FC 等变量指向 GCC 11.3.0 的对应程序，并指定安装前缀（如 `/public/home/tom/opt/mpich-4.0.3`）。完成配置后，使用 `make -j 24` 进行编译并执行 `make install` 安装。

---

## 11. Slurm 作业脚本环境配置示例

在 Slurm 作业脚本中，需要正确设置 Singularity 容器路径、GCC 环境和 MPI 环境。首先定义 Singularity 执行变量 `export EXE="singularity exec /path/to/cp2k2023.1.sif"`。接着依次导出 GCC 11.3.0 的 PATH 和 LD_LIBRARY_PATH，以及 MPICH 的 MPI_HOME、PATH 和 LD_LIBRARY_PATH。最后使用 `mpirun -np $SLURM_NPROCS ${EXE} cp2k.popt cp2k.inp` 启动并行计算任务。

---

## 12. 单机或非调度系统运行 CP2K

在不使用 Slurm 等调度系统的单机环境下，可以直接调用容器内的 mpirun 运行 CP2K，无需额外安装和配置外部的 GCC 和 MPI。命令示例为 `singularity exec /path/to/cp2k2023.1.sif mpirun -np 36 cp2k.popt cp2k.inp`。这种方式利用了容器内预先配置好的完整并行环境，简化了运行步骤。
