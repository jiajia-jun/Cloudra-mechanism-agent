## 1. CentOS 8.5 Stream 镜像源配置

配置 CentOS 8.5 Stream 的安装源可使用阿里云镜像。在 `/etc/yum.repos.d/` 目录下，将原有文件移至 `bak` 文件夹，保留或新建 `centos-base.repo` 文件并填入阿里云 vault 源配置。配置完成后运行 yum 命令验证并安装相关软件，EPEL 源可通过 `yum install epel-release` 自动生成。
- 阿里云 CentOS Vault 源地址示例：`http://mirrors.aliyun.com/centos-vault/8.5.2111/BaseOS/$basearch/os/`
- GPG 检查参数设置为 0：`gpgcheck=0`

---

## 2. 集群节点 UID 与 GID 同步

计算节点与控制节点的用户 UID 和 GID 必须保持一致。可使用 `sudo id (用户名)` 查看用户信息，使用 `sudo usermod -u (UIDs) (用户名)` 和 `sudo groupmod -g (GIDs) 组名` 进行修改。
- 建议先手动创建 munge 和 slurm 账号以确保 UID/GID 一致。

---

## 3. 集群时间同步配置

集群各节点时间必须同步，CentOS 最小化安装默认包含 `chronyd` 服务。使用命令 `systemctl start chronyd && systemctl enable chronyd` 启动并设置开机自启，若节点无法自动同步则需手动配置。同步完成后可将时间写入 CMOS：`clock -w && hwclock -systohc`。
- 查看当前时间命令：`date`

---

## 4. 旧版 Munge 与 Slurm 清理

重新安装前需彻底删除之前失败的安装残留。可使用 `yum remove munge munge-libs munge-devel -y` 删除 Munge 相关包，并参考相关文档清理 Slurm 残留文件和配置，以避免新安装出现冲突。

---

## 5. Munge 用户手动创建

建议在安装 Munge 前手动创建 munge 账号以统一各节点 UID 和 GID。设置环境变量 `export MUNGEUSER=1007`（可选用未占用的数值），使用 `groupadd` 和 `useradd` 创建账号，确保所有计算节点执行相同操作。
- 示例命令：`useradd -m -c "MUNGE Uid 'N' Gid Emporium" -d /var/lib/munge -u $MUNGEUSER -g munge -s /sbin/nologin munge`

---

## 6. Munge 源码编译安装

从 GitHub 下载 Munge 源码包 `munge-0.5.14.tar.xz` 并使用 `rpmbuild` 编译 RPM 包。若编译过程提示缺少依赖，可使用 `yum search` 查询并用 `yum install` 安装，或百度搜索 "依赖名 centos 8 rpm" 下载缺失的 RPM 包。
- 编译命令：`rpmbuild -tb --without verify munge-0.5.14.tar.xz`

---

## 7. Munge RPM 包安装

编译生成的 RPM 包位于 `~/rpmbuild/RPMS/x86_64` 目录下。使用 `rpm -ivh` 命令按顺序安装 munge、munge-devel 和 munge-libs 等包，安装包名称需根据实际编译结果调整。这些 RPM 包需要在控制节点和所有计算节点上安装。
- 示例命令：`rpm -ivh munge-0.5.14-1.el8.x86_64.rpm munge-devel-0.5.14-1.el8.x86_64.rpm munge-libs-0.5.14-1.el8.x86_64.rpm`

---

## 8. Munge 密钥生成与同步

在控制节点使用 `sudo -u munge /usr/sbin/mungekey -v` 生成密钥，文件位于 `/etc/munge/munge.key`。必须将此密钥同步复制到所有计算节点的相同路径下，确保各节点密钥一致。
- 计算节点也需执行生成密钥命令或直接复制控制节点的密钥文件。

---

## 9. Munge 服务启动

使用 `systemctl` 命令启用并启动 Munge 服务。通过 `systemctl status munge` 检查服务运行状态，确保服务正常启动。
- 启动命令：`systemctl enable munge && systemctl start munge`

---

## 10. Slurm 用户创建

安装 Slurm 前需创建 slurm 系统账号，并确保控制节点与计算节点的 UID 和 GID 一致。可使用 `useradd` 和 `groupmod` 命令指定 UID 创建账号和组。
- 示例命令：`useradd -u (uid) slurm && groupmod -g (gid) slurm`

---

## 11. Slurm 依赖安装

使用 `yum search slurm` 查找 Slurm 相关包，并通过 `yum install` 安装。若仓库中缺少依赖，需手动下载并安装缺失的 RPM 包（如 libaec）。
- 示例命令：`yum install (slurm相关包名) -y`

---

## 12. Slurm 配置文件设置

编辑 `/etc/slurm/slurm.conf` 文件，设置控制节点名称、IP 地址、节点名称及资源配置。`RealMemory` 设置不宜过大，否则可能导致节点不可用。
- 配置示例：`ControlMachine=控制节点主机名`、`NodeName=n[1-2] CPUs=64 RealMemory=510000 TmpDisk=64000 State=UNKNOWN`

---

## 13. Slurm 服务启动

在控制节点运行 `slurmctld` 和 `systemctl start slurmctld`，在计算节点运行 `slurmd` 和 `systemctl start slurmd`。启动前可使用 `-c` 参数测试配置文件正确性。
- 控制节点命令：`slurmctld -c && systemctl start slurmctld && systemctl enable slurmctld`

---

## 14. Slurm 作业提交脚本

作业提交脚本需包含 `#SBATCH` 开头的资源声明及执行命令。脚本编写完成后使用 `sbatch` 提交，可通过 `sinfo`、`squeue` 和 `scontrol show node` 查看系统状态和作业信息。
- 示例脚本内容：`#!/bin/bash`、`#SBATCH --partition=longtime`、`mpirun -n 64 ~/bin/vasp_std`

---

## 15. 集群节点故障排查与 IPMI 内存检测

若计算节点出现 "not responding" 状态，重启 Slurm 服务可能恢复。问题可能由内存硬件错误引起，可使用 `ipmitool sel elist` 查看系统事件日志（SEL）以定位内存故障。
- 故障恢复操作：重启 Slurm 服务，检查物理内存。
